# 출석 시간 설정과 자동 결석

관련 이슈: https://github.com/depromeet/dpm-core-server/issues/573

## 환경변수 기본값

| 환경변수 | 기본값 | 의미 |
|---|---|---|
| ATTENDANCE_OPEN_MINUTES_BEFORE_START | 10 | 시작 몇 분 전 인증 시작 |
| ATTENDANCE_LATE_AFTER_START_MINUTES | 15 | 시작 몇 분 후 지각 |
| ATTENDANCE_ABSENT_AFTER_START_MINUTES | 30 | 시작 몇 분 후 마감 |

기본값은 0~1440분이며 인증 시작 < 지각 시작 < 마감 순서를 기동 시 검증한다. 설정 변경은 재시작 후 적용된다. 정책 조회·수정 API 및 정책 테이블은 없다.

세션 시작을 T, 서버 인증 요청 시각을 t라고 하면 기본값은 다음과 같다.

- 출석: T-10분 ≤ t < T+15분
- 지각: T+15분 ≤ t < T+30분
- 인증 마감: T+30분 ≤ t

## 세션 생성 및 변경

`POST /v1/sessions`에서 attendanceStart, lateStart, absentStart를 모두 생략하면 서버가 환경변수 기본값으로 계산해 세션에 절대 시각을 저장한다.

기존 클라이언트처럼 세 시각을 모두 보내면 명시적인 세션별 설정으로 사용한다. 일부만 보내는 요청은 거절한다.

환경변수 기본값 변경은 기존 세션의 시각이나 기록을 바꾸지 않는다. 이미 만든 세션의 시각은 기존 세션 수정 API로 변경한다.

멤버의 출석 인증 요청에는 시각을 넣지 않는다. `POST /v1/sessions/{sessionId}/attendances`에는 출석 코드만 보내며, 서버가 요청 처리 시작 시각을 기록한다.

## 인증 마감과 자동 결석

인증 마감은 요청 처리 시 즉시 검사한다. 마감 후 유효한 코드를 입력해도 인증 성공으로 응답하지 않는다.

자동 결석 스케줄러는 이전 실행 종료 후 30초 뒤에 다시 실행한다. 미인증자만 결석으로 바꾸며 운영진 변경 및 기존 인증 결과는 보호한다. 따라서 마감과 결석 저장 사이에는 실행 주기와 작업 시간에 따른 지연이 있다.

자동 결석은 항상 켜져 있으며 기간 하한이 없다. 과거 기수를 포함해 인증 마감이 지난 모든 세션의 미인증(PENDING, 인증·운영진 변경 없음) 기록을 결석으로 바꾼다. 따라서 배포 후 첫 실행에서 과거 세션의 미인증 기록도 결석 처리된다. 서버 중단 후 재시작하면 그동안 지난 마감도 모두 처리한다. 출석·지각·인정 결석·운영진 변경 기록과 자동 결석 표지가 없는 기존 결석은 바꾸지 않는다.

마감 전에 접수된 정상 인증은 자동 결석 저장이 먼저 끝났더라도 원래 요청 시각대로 반영한다. 자동 결석은 별도 처리 시각으로 출처를 구분한다.

새로 활성화된 멤버에게는 이미 마감된 세션의 출석 기록을 새로 만들어 가입 전 결석을 소급 부과하지 않는다. 기존 출석 기록은 유지한다.

## 배포와 검증

배포 전에 `db/pending/2610011200_attendance_auto_absence.sql`을 검토하고 적용해야 한다. 애플리케이션은 스키마를 검증하므로 auto_absent_at 컬럼과 인덱스를 먼저 추가해야 한다. 저장소 작업 과정에서 운영 DB에는 적용하지 않는다.

일반 테스트: `./gradlew :application:test`

실제 MySQL 동시성 테스트: 로컬의 일회용 `dpm_it*` DB를 준비하고 다음 환경변수로 실행한다. 이 테스트는 해당 DB의 스키마를 생성한다.

```sh
DPM_IT_MYSQL_URL='jdbc:mysql://127.0.0.1:3307/dpm_it_attendance?serverTimezone=Asia/Seoul' \
DPM_IT_MYSQL_USERNAME=root DPM_IT_MYSQL_PASSWORD='<test password>' \
./gradlew :application:mysqlIntegrationTest
```

수료 기준, 경조사·취업 증빙 예외 정책, 프론트 화면 갱신은 이번 시간 정책 변경 범위에 포함하지 않는다.
